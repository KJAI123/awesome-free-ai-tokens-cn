# 免费 AI 额度怎么核验：到账、积分、模型用量分开看

整理日期：2026-11-23（北京时间）。本文介绍核验方法；案例保留各自的核验时间，不是长期有效的领取承诺。

维护者说明：本仓库与 TokenMost 由同一维护者维护。本文基于公开规则与脱敏调用记录整理，不出售平台额度。

## 先记原单位，再决定能否换算

领取页里的三个数字可能表示完全不同的东西：

| 页面写法 | 先记录什么 | 不能直接推断什么 |
|---|---|---|
| 赠送若干 Token | 数量、可用模型、客户端或 API、到期时间 | 不代表所有模型都可用，也不代表现金余额 |
| 每日若干积分或调用次数 | 原始日额、刷新时间、扣费表或调用上限 | 没有官方比例时，不能硬算成固定 Token |
| 套餐最高若干美元用量 | 订阅价、共享额度、模型及窗口限制 | 模型用量上限不是可提现美元，也不是逐模型各有一份 |

金额、积分、Token 分列，才能避免把一种权益重复记成几份。只有官方给出换算比例时，才记录对应模型、输入输出比例、缓存和时段；情景估算另外标出假设与区间。

## 一条权益至少核对八项

1. **入口**：官方活动页、定价页或文档具体在哪里？
2. **对象**：新用户、老用户、学生或申请制？本人账号是否符合？
3. **动作**：注册、登录桌面端、签到、订阅还是人工领取？
4. **原始额度**：究竟是积分、Token、调用次数还是模型用量？
5. **可用范围**：具体模型、客户端/API，以及是否与其他模型共享池？
6. **周期**：一次性、每日、每周还是每月刷新？未用完是否结转？
7. **截止**：领取窗口和使用有效期分别是什么，采用哪个时区？
8. **证据时间**：本轮看到了条款，还是本轮实际领取或调用成功？

把“条款已核对”“本人已到账”“历史调用通过”“当前待复核”分别记录。页面能打开，不能代替到账或调用测试。

## 案例一：邀请增量不要与新人组合总额重复相加

2026-11-22 核对的 [TRAE 官方邀请规则](https://docs.trae.cn/ide_invite-new-users-to-earn-credits-for-traecode)说明：符合资格的新用户通过专属链接首次注册并登录桌面端，双方各得 500 通用积分。活动截止为 2026-11-30 00:00（北京时间），邀请积分发放后 31 天有效，不能兑现金。

这个结论支持的是**邀请增量 500**。若另一个页面写“新人福利＋邀请奖励合计 2500”，应先拆开组成，核对基础赠额及登录福利，再判断其中是否已经包含这 500。不能把组合总数和邀请增量再加一次。

这也不证明某个具体账号已到账：账号资格、实际领取动作和账户记录仍需分别确认。活动结束后，本段仅作为核验方法案例。

## 案例二：昨天 HTTP 200，不代表今天仍然能调用

2026-11-21 的一次本地 FreeLLMAPI 测试中，NVIDIA 的 `nvidia/nemotron-3.5-lightning-30b-a3b` 普通与流式请求均返回 HTTP 200。这个记录只支持该日期、该模型及当次测试路径；不支持全部模型可用、整月容量或自动故障切换。

临时测试 Key 后来过期，本地路由也停止运行。因此，恢复前应重新核对本人 Key、模型可用性和服务状态。该个案不能用来推断所有 NVIDIA Key 都具有相同有效期。

可对照 [NVIDIA 官方接入文档](https://docs.api.nvidia.com/nim/docs/api-quickstart)，以及我们公开的 [本地调用记录与接入说明](https://tokenmost.com/guides/freellmapi.html)。后续测试请只在本人环境保存 Key，公开记录中保留模型、时间、HTTP 状态、响应摘要与耗时，去掉密钥和身份信息。

## 可复用的核验表

| 字段 | 填写方式 |
|---|---|
| 原始权益 | 保留页面原单位，不先换算 |
| 官方依据 | 具体规则 URL 与读取日期 |
| 领取与使用条件 | 账号资格、必需动作、模型和端/API 范围 |
| 刷新与截止 | 周期、有效期、时区、是否结转 |
| 实测 | 实测日期、操作范围及脱敏结果；没有实测就留空 |
| 当前结论 | 已核条款 / 本人已到账 / 历史通过 / 待复核 / 已过期 |
| 未确认项 | 明确写出欠缺证据，交付前再核对 |

用这张表记录，读者可以复查结论，也能知道哪些信息需要重新验证。阅读清单的价值在于减少重复核对工作，而不是保证每个人都能拿到页面上的最大数字。
